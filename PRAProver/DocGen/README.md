# PRA documentation

Build the documentation for `PRAProver.lean` and its imports:

```sh
lake build PRAProver:docs
```

Open `.lake/build/doc/index.html`. The generated site uses relative links and runs name search in
the browser.

To extract documentation data for one module:

```sh
lake build PRAProver.Library.Nat.Defs:docs
```

This writes `.lake/build/doc-data/PRAProver.Library.Nat.Defs.json`. The library facet collects these
per-module files and assembles the website. Lake tracks the compiled generator and module artifacts.
Site assembly caches input file sizes and modification times, renderer code, assets, and the output
file inventory in `.lake/build/doc.cache.json`. The generated directory is replaced when rebuilt.

## Content

Each module containing PRA declarations gets one page. Pages show function and predicate
definitions with collapsed bodies, and theorems with their parameters and conclusions. Declarations
follow their Core export order, including declarations generated by tactics. Module comments appear
between declarations according to their source positions. Docstrings and module comments support
Markdown paragraphs, headings, lists, blockquotes, emphasis, links, inline code, and fenced code
blocks. Raw HTML is escaped.

The left sidebar shows the module tree; the right sidebar lists the page's declarations. Search
covers every declaration in the site. `manifest.json` records the module and declaration counts.

The printer reconstructs expressions from Core syntax. It uses fresh binder names and named implicit
schema arguments. Registered binary notation displays fully applied definitions with their symbols,
such as `x ≤ y` for `LE x y`, using the parser's precedence and associativity. Other notation forms,
bare names, and partial applications use ordinary names and application. Global references link to
declarations included in the site, including references displayed as notation symbols.

## Implementation

Lake builds the `praDocGen` executable for extraction and site assembly. Extraction reads the
target's `.olean` export first. An empty declaration list produces an empty data file; a populated
module loads its imports for notation, docstrings, and declaration context.

- `Pretty.lean` reconstructs signatures and definition bodies from Core syntax. Its `Context`,
  `CodeSpan`, and `render` interfaces carry global reference identities through formatting.
  `Context.withNotations` reads binary notation from Surface's registry.
- `Writer.lean` extracts declarations, module comments, and editor docstrings. Declarations without
  source locations are placed alongside the next located declaration; trailing ones stay at the
  end. If a module has no declaration locations, its comments appear first.
- `Site.lean` renders Markdown, resolves links, and writes pages, navigation, the search index,
  and the manifest.
- `Driver.lean` dispatches build operations; `Main.lean` is the executable's entry point.
- `style.css` and `search.js` provide layout and search.
